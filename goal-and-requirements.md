# Замер скорости интернета

Консольный скрипт, который качает заданный URL 10 раз подряд и печатает скорость скачивания.

## Overview

Тестовое задание: учебный CLI-замер скорости интернета. Скрипт принимает адрес (например, тяжёлую картинку), делает к нему 10 последовательных запросов, дожидаясь полного ответа на каждый, считает среднее время запроса и общий объём скачанных данных и печатает скорость скачивания.

## Problem

Проверить скорость соединения до конкретного хоста — руками через браузер или сервисы типа speedtest.net, которые меряют не тот путь и не те единицы. Нужен минимальный инструмент: один файл, один аргумент, понятный ответ.

## Capabilities

- Принимает URL аргументом командной строки (обязательный).
- Делает один warmup-запрос вне замера (компенсирует TCP slow start и «холодное» соединение), затем 10 последовательных тестовых GET-запросов, каждый раз дочитывая тело ответа до конца.
- Считает среднее время запроса и суммарный объём скачанных тел ответов.
- Печатает краткий итог: среднее время, общий объём, скорость в Мбит/с.
- Если часть запросов упала (сеть, HTTP-ошибка, таймаут): печатает предупреждение и считает итоги по успешным запросам.

## Tech Notes

- Язык: Python 3. `requests` для HTTP — единственная зависимость.
- Одна `requests.Session` на весь замер (keep-alive): TCP+TLS+DNS платим один раз, а не десять.
- Запрашиваем `Accept-Encoding: identity` и считаем объём по факту скачанных байт (streaming), иначе сжатие исказит объём.
- Скорость в Мбит/с (мегабиты, как у провайдеров); формула: `скорость = (Σ байт × 8) / Σ время / 1e6`; в README явно указать ×8 к мегабайтам.
- Тестовый URL должен вести на файл 25–100 MB: на мелких файлах замер измеряет латентность и slow start, а не пропускную способность (на 100 КБ при канале 100 Мбит/с результат занижается в десятки раз); слишком большие файлы растягивают замер и съедают трафик без прироста точности.
- За образец полноты НЕ берём speedtest-cli (sivel): он меряет через чужой API и многопоточность, что противоречит заданию. Однопоточный замер последовательных запросов заведомо ниже максимума канала — зафиксировать это ограничение в README.
