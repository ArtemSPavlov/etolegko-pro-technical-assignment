# Замер скорости интернета

Консольный скрипт на Python: делает 10 последовательных запросов к заданному URL
(например, к тяжёлой картинке или тестовому файлу), дожидается полного ответа
на каждый и печатает скорость скачивания.

## Требования

- Python 3.8+
- `requests` — единственная зависимость: `pip install requests`

## Запуск

```bash
python3 speed_test.py <URL>
```

Пример (тестовый файл 50 МБ от Cloudflare — размер задаётся параметром `bytes`):

```bash
python3 speed_test.py "https://speed.cloudflare.com/__down?bytes=50000000"
```

> Если пример не открывается (провайдерская блокировка, гео-ограничение) — возьмите
> любой другой прямой URL на файл 25–100 МБ: зеркала дистрибутивов Linux, тестовые
> файлы хостеров (например `https://ash-speed.hetzner.com/100MB.bin`).

Пример вывода:

```
Среднее время запроса: 8.34 с
Скачано всего: 1000.0 МБ
Скорость скачивания: 96.12 Мбит/с
```

## Единицы измерения

- **Скорость — мегабиты в секунду (Мбит/с)**, как у интернет-провайдеров и speedtest.net.
  1 Мбит/с = 0,125 МБ/с (мегабайт в секунду); чтобы получить МБ/с, разделите на 8.
- Объём печатается в мегабайтах (МБ), время — в секундах.

## Как считается

```
скорость (Мбит/с) = суммарный объём тел ответов × 8 / суммарное время / 1 000 000
```

Детали реализации:

- Перед замером выполняется один warmup-запрос вне статистики — он «разогревает»
  TCP-соединение (slow start), чтобы первый тестовый запрос не занижал среднее.
- Все запросы идут через одну `requests.Session` (HTTP keep-alive): TCP+TLS+DNS
  выполняются один раз, а не десять.
- Запрашивается `Accept-Encoding: identity`, объём считается по реальным байтам тела —
  сжатие не искажает замер.
- Если часть запросов упала (сеть, HTTP-ошибка, таймаут 30 с), скрипт печатает
  предупреждение и считает итоги по успешным запросам.

## Ограничения метода

- Замер **однопоточный и последовательный** (так требует задание). На быстрых
  каналах (>200–500 Мбит/с) одно TCP-соединение может не заполнить канал целиком —
  результат будет ниже цифр speedtest.net, который использует несколько потоков.
- Тестовый URL должен вести на файл **25–100 МБ**. На мелких файлах замер измеряет
  в основном латентность и время установления соединения, а не пропускную
  способность: на файле 100 КБ при канале 100 Мбит/с результат занижается в десятки раз.
- Результат отражает скорость до конкретного хоста в конкретный момент, а не
  максимум вашего тарифа.
